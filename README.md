# Tone Analyzer

Reference 이미지의 톤과 색감을 Target 이미지에 옮기고, 그 변환을 **DaVinci Resolve 등에서 바로 쓸 수 있는 3D LUT(`.cube`)** 로 내보내는 Streamlit 웹 앱입니다.

컬러리스트의 작업 순서를 그대로 따릅니다.

```text
⓪ 레터박스 / 필러박스 자동 제거
        ↓
① 프라이머리 (파형 기준점)
   Lift(블랙) → Gain(화이트) → 보간 → Gamma(중앙값) → Contrast/Pivot   ─▶ 노드 1
        ↓
② 화이트밸런스 (중성색)                                                ─▶ 노드 2
        ↓
③ 채도 (피부 채도 기준)                                                ─▶ 노드 3
        ↓
④ 색작업 (톤 영역별 색) + 피부 보호 · 강도                              ─▶ 노드 4
        ↓
⑤ 피부톤 (퀄리파이어: Reference 피부의 색상 · 밝기에 맞춤)             ─▶ 노드 5
        ↓
.cube 내보내기 (전체 하나 / 노드별 5개)
```

시니어 컬러리스트의 노드 순서(Balance → Contrast → Saturation → Look → Skin)와 shot matching 원칙을 따릅니다.
두 이미지의 파형 **전체 모양이 아니라 서로 대응하는 지점**(블랙 바닥, 화이트 피크, 미드톤, 중성색, 피부)을 맞춥니다.
화면 내용이 다르면(검은 옷이 많은 컷, 네온이 많은 장면) 전체 모양은 원래 다르기 때문입니다.

---

## 빠른 시작

```bash
# 의존성 설치 (Python 3.12, uv 사용)
uv sync

# 웹 앱 실행
uv run streamlit run src/tone_analyzer/app.py
```

1. **Reference**(따라 하고 싶은 룩)와 **Target**(보정할 이미지)을 업로드합니다.
2. 사이드바의 **학습 설정**을 확인하고 `톤 매칭 시작`을 누릅니다.
3. **실시간 조절**(LUT 강도, 피부톤 보호)을 움직이며 결과를 확인합니다. 재학습 없이 바로 반영됩니다.
4. 원하는 설정에서 LUT를 다운로드합니다.

## 어떤 LUT를 받아야 하나요?

| DaVinci 에서의 사용 방식 | 받을 파일 |
|---|---|
| LUT 하나로 끝내기 | **전체 ①~⑤** (`..._{N}_sXXX_skinYYY_fixZZZ.cube`) |
| 노드를 나눠 단계별로 조절 | 노드 1 `_1_primaries` → 2 `_2_wb` → 3 `_3_sat` → 4 `_4_color` → 5 `_5_skin` (차례로 건 결과 = 앱 결과) |
| ①~③은 휠로 직접 맞추기 | **노드 4, 5** 만 — 앱의 추정값(파형 기준점 표)에 가깝게 맞춘 뒤 사용 |
| 피부톤은 DaVinci 퀄리파이어로 직접 | 노드 1~4 만 |

> ⚠️ **색공간 주의**: LUT는 Rec.709 디스플레이 이미지(JPG/PNG/스크린샷) 기준으로 만들어집니다.
> S-Log, LogC 등 로그 소스에는 먼저 CST/변환 LUT로 Rec.709 로 바꾼 **다음 노드**에 거세요.

> 실시간 조절 값은 **다운로드 시점의 값으로 LUT에 고정**됩니다. 파일 이름의 `s080_skin085_fix050` 은 LUT 강도 0.80, 피부 보호 0.85, 스킨톤 교정 0.50 을 뜻합니다.

## 처리 과정

### ⓪ 레터박스 자동 제거 (`letterbox.py`)

영화 캡처의 위아래(좌우) 검은 띠가 '블랙'으로 통계에 섞이면 ① 블랙 포인트가 틀어집니다. 분석 전에 Reference·Target 모두 잘라냅니다. (`auto_crop=True`, 앱 "레터박스 자동 제거")

1. 가장자리 2줄의 밝기 중앙값을 그쪽 **띠 색**으로 잡습니다 (0 이든 영상의 16 이든).
2. 줄마다 **띠 줄**인지 판정: 중앙값이 띠 색과 거의 같고, 띠 색보다 밝은 픽셀이 20% 이하(자막·재생바 허용)이고, 나머지가 고름.
3. 가장자리에서 안쪽으로 훑다가 띠가 아닌 줄이 3줄 연속이면 경계.
4. 검증: 경계 안쪽이 띠 색보다 확실히 밝아야 자릅니다 (**밤하늘처럼 서서히 밝아지는 가장자리는 자르지 않음**). 이미지 거의 전체가 검으면 자르지 않고 경고.
5. 경계에서 2px + 0.2% 더 잘라 압축 번짐을 뺍니다.

- **위아래 대칭은 요구하지 않습니다.** Mac 스크린샷은 메뉴바·노치 때문에 위 178 / 아래 112 처럼 비대칭인 경우가 실제로 있습니다. 한쪽에만 띠가 있으면 신뢰도 `low` 로 표시합니다.
- 잘라낸 비율이 2.39 / 1.85 / 16:9 같은 알려진 화면비에 가까우면 함께 표시합니다.
- 결과 이미지도 잘린 크기로 나옵니다.

### ① 프라이머리 — 파형 기준점 순서대로 (`primaries.py`)

**밝기 계조만** 다룹니다. 컬러리스트가 파형 모니터를 보며 하는 순서 그대로, 단계마다 **맞추는 지점을 하나씩** 정해 차례로 풉니다. 루마는 Rec.709 (파형과 같은 값), RGB 세 채널에 같은 값을 쓰는 **마스터 휠**입니다.

| 순서 | 휠 | 맞추는 지점 | 수식 |
|---|---|---|---|
| 1 | **Lift** | 블랙 포인트 (하위 0.5%) → Reference 블랙 | `y = x + lift·(1 − x)` |
| 2 | **Gain** | 화이트 포인트 (상위 0.5%) → Reference 화이트 | `y = y · gain` |
| 3 | **보간** | Gain 이 블랙을, Lift 가 화이트를 조금씩 움직이므로 1·2 를 번갈아 반복 (오차 0.1% 이내까지) | |
| 4 | **Gamma** | 전체 루마 중앙값 → Reference 중앙값. **블랙·화이트는 고정** | `n = (y − 블랙)/(화이트 − 블랙)`, `n' = n^(1/gamma)` |
| 5 | **Contrast / Pivot** | 25~75% 폭(계조) → Reference 폭. 피벗 = Reference 중앙값 | 블랙·화이트·피벗을 고정한 **S 커브** (DaVinci "Use S-curve for contrast" 방식), 피벗에서 기울기 = contrast |

- 블랙·화이트 목표는 **Reference 의 레벨 그대로**입니다. 영화가 블랙을 띄워 놨으면 그것도 따라갑니다.
- **안전 범위** (기본 켜짐): 블랙·화이트는 어느 장면에나 있어 화면 내용에 강하지만, 미드톤(Gamma)·계조(Contrast)는 내용에 흔들립니다. Gamma 0.8~1.25, Contrast 0.85~1.2 를 벗어나면 **범위 끝에 붙이지 않고 원래 값 쪽으로 줄입니다.** 범위를 r 배 넘으면 범위 끝의 1/r 만큼만 적용합니다 (많이 벗어날수록 '노출 차이가 아니라 내용 차이'일 가능성이 크므로).
  예) 계산 Gamma 1.51 → 적용 1.13 / 실제 리버스 숏: 계산 0.50 → 적용 0.93
- 앱의 **파형 기준점 표**에 블랙·미드톤·화이트·계조의 Reference / Target 전 / 후 값(%)이 나옵니다. DaVinci 휠을 직접 만질 때 그대로 보면서 맞추면 됩니다.
- **① 강도** (기본 1.0): 0 이면 밝기·대비를 건드리지 않습니다.

이전 방식인 **히스토그램 매칭 커브**(Lab L 채널, 101포인트)도 `톤 단계 방식`에서 선택할 수 있습니다. 분포를 그대로 복사하므로 화면 내용 차이까지 커브에 반영됩니다.

### ② 화이트밸런스 (`white_balance.py`)

① 을 적용한 이미지에서 **원래 회색이어야 할 픽셀**(루마 20~97%, 상대 채도 하위 20%, 피부 제외)의 Lab a·b 중앙값을 찾고, Temp / Tint 로 옮깁니다.

| 기준 | 동작 |
|---|---|
| **중성색을 회색으로** (기본) | 중성색을 실제 회색(a = b = 0) 쪽으로 보정. 컬러리스트의 밸런스 작업이며, 룩의 색감은 ④ 가 담당 |
| Reference 의 중성색에 맞춤 | 중성색을 Reference 의 중성색 쪽으로. Reference 의 회색에 섞인 룩 색감(예: 틸)까지 따라감 |

```text
gain_R = exp(+temp),  gain_G = exp(-tint),  gain_B = exp(-temp)
gains  = gains / luma(gains)        # 밝기 유지
temp > 0 : 따뜻하게,  tint > 0 : 마젠타 쪽
```

- `② 화이트밸런스 강도`(기본 0.7): 1 이면 완전히 회색으로. 텅스텐 조명의 따뜻함처럼 의도된 조명 색을 조금 남기도록 0.7 을 기본으로 합니다.
- 얼굴에서 샘플링한 피부 색은 중성색 후보에서 뺍니다.
- Temp / Tint 는 이 앱의 단위입니다(DaVinci 의 K 값과 다름). DaVinci 에는 함께 표시되는 **RGB Gain 비율**로 옮기는 것이 정확합니다.

> **DaVinci 수식과의 차이**: Resolve 내부 수식은 공개되어 있지 않아 ①~③ 값은 표준 공식 기준의 **근사값**입니다. 휠에 옮겨 넣을 때는 시작점으로 쓰고 눈으로 미세 조정하세요. LUT 는 근사가 아니라 앱 결과 그대로입니다.

### ③ 채도 (`saturation.py`)

밝기와 색 균형을 맞춘 뒤 벡터스코프의 퍼짐을 Reference 에 맞춥니다. DaVinci Saturation 처럼 루마는 그대로 두고 색 성분만 키우거나 줄입니다 (`y = luma + sat·(rgb − luma)`).

| 기준 | 언제 |
|---|---|
| **피부 채도 비율** | 두 이미지 모두 얼굴이 있을 때. 피부는 장면이 달라도 비교할 수 있는 공통 기준이라 화면 내용에 강합니다 |
| 미드톤 채도 (상위 25% 지점) 비율 | 얼굴이 없을 때 |

- 안전 범위 0.8~1.25, 벗어나면 ① 과 같은 방식으로 줄입니다. `③ 채도 강도`(기본 1.0)
- 네온이 가득한 장면과 회색 벽 장면을 통째로 비교하면 채도가 엉뚱하게 움직이므로, 장면 전체 분위기의 채도 차이는 ④ 색작업이 일부 담당합니다.

### ④ 컬러 그레이딩 — 분포 기반 색 전이 (`color_matching.py`)

Reference 와 Target 은 **서로 다른 사진**이므로 같은 좌표의 픽셀끼리는 아무 관계가 없습니다. 그래서 다음과 같이 학습 데이터를 만듭니다.

```text
Target 픽셀 샘플링 ─┐
                    ├─▶ Target 색 분포를 Reference 분포로 전이
Reference 픽셀 샘플링 ┘
        ↓
(Target 원본 픽셀, 같은 픽셀의 전이 결과) = 학습 쌍
        ↓
3차 다항식 + Ridge 회귀로 부드러운 RGB→RGB 매핑 학습
        ↓
3D LUT 격자점(17³ / 33³ / 65³) 계산
```

색 전이 방식:

| 방식 | 설명 |
|---|---|
| **reinhard** (기본) | Lab 평균/표준편차 매칭. `톤 영역별 색 전이`를 켜면 섀도우/미드/하이라이트 각각 따로 맞춘 뒤 부드럽게 섞음 (스플릿 토닝 재현) |
| **idt** | Iterative Distribution Transfer (Pitié 2005). 분포 전체를 맞추므로 강하지만, Reference 의 특정 색이 엉뚱한 곳으로 번질 수 있음 |

`밝기는 1D 톤 커브 유지`(기본 켜짐)를 켜면 밝기는 톤 단계 결과를 유지하고 색(Lab a, b)만 옮깁니다.

채도는 ③ 이 맡으므로 ④ 는 **색 방향**(평균 이동, 스플릿 톤) 위주로 옮기고, 색 퍼짐(분산) 배율은 제곱근으로 약하게만 따릅니다 (`CHROMA_STD_EXPONENT = 0.5`).

### 피부 인식 (`skin_tone.py`, `models/`)

④ 피부 보호와 ⑤ 스킨톤 교정은 모두 **얼굴에서 직접 샘플링한 피부 색 범위**를 기준으로 합니다.

1. [YuNet](https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet) 얼굴 인식 (OpenCV 내장 `FaceDetectorYN`, 모델 230KB, MIT License) 으로 얼굴 위치를 찾습니다.
2. 얼굴 안쪽 타원(볼·이마·코)에서 피부 픽셀을 뽑고, 눈·눈썹·머리카락·입술 같은 이상치를 걸러냅니다.
3. 샘플의 색상·채도·밝기 분포로 **피부 색 범위(퀄리파이어)**를 만듭니다.
   - ④ 보호: ①②③ 이후 피부 색 범위
   - ⑤ 교정: 피부 샘플을 ④ 에 통과시킨 **그레이딩 후 피부** 색 범위
4. **얼굴을 못 찾으면 ④ 피부 보호와 ⑤ 교정을 건너뜁니다.** 사람이 없는 장면에서 나무·모래·노을 같은 따뜻한 색을 피부로 처리하지 않기 위해서입니다. 뒷모습이나 아주 작은 인물처럼 사람은 있는데 얼굴이 안 잡히는 경우에는 `얼굴이 없어도 색 기준으로 피부 처리`(실시간)를 켜면 색만으로 피부를 추정해 처리합니다. 코드에서는 `skin_without_face=True`.

- **배경 누출 경고**: 피부 색 범위에 해당하는 영역 중 얼굴 밖 비율이 5% 를 넘으면 경고합니다. (예: 따뜻한 조명 아래 나무·벽이 피부와 같은 색인 장면)
- **Reference 피부 신뢰도**: Reference 얼굴이 너무 어둡거나 무채색(채도 < 6)이면 측정값을 쓰지 않고 스킨톤 라인을 목표로 합니다.
- 앱의 "피부 인식 확인"에서 인식한 얼굴과 피부 마스크를 볼 수 있습니다.

### 피부톤 보호 · 강도 (`lut.py`)

두 기능 모두 **학습이 아니라 LUT 격자점에 직접** 적용되므로 `.cube` 에 그대로 반영되고, 앱에서 실시간으로 조절됩니다.

- **피부톤 보호**: 각 격자점의 입력 색이 피부색일 가능성(Lab 색상각 약 0~65°, 적당한 채도, 중간 밝기)을 계산하고, 그만큼 출력을 원래 색으로 되돌립니다. 피부색은 RGB 공간에서 얇은 영역이라 보간 중 보호가 새지 않도록 가중치를 이웃 격자로 한 칸 넓힙니다(3×3×3 dilation).
- **LUT 강도**: `identity × (1 − s) + LUT × s`

| 피부 보호 | 0 | 0.6 | 0.85 | 1.0 |
|---|---|---|---|---|
| 피부 영역 평균 ΔE (강도 0.8, 예시 이미지) | 14.9 | 5.9 | 2.2 | 0.1 |

### ⑤ 피부톤 — 퀄리파이어로 색상 · 밝기 맞추기 (`skin_tone.py`)

④ 까지 적용한 색에서 피부로 추정되는 색만 골라 **색상(hue)을 목표 쪽으로 당기고 채도를 조절**합니다. DaVinci 에서 피부를 퀄리파이어로 잡고 Hue / Sat 을 만지는 작업에 해당합니다. (④ 의 '피부 보호'는 룩 때문에 피부가 틀어지지 않게 *되돌리는* 것이고, ⑤ 는 피부를 *교정*하는 것입니다.)

| 설정 | 기본값 | 설명 |
|---|---|---|
| 교정 목표 | Reference 피부 | Reference 얼굴의 피부 색상 (영화의 피부 톤). Reference 에서 얼굴을 못 찾았거나 너무 어둡거나 무채색이면 벡터스코프 I 라인 (Lab 색상각 약 62°) |
| 색상 교정 강도 | 0.5 | 피부 색상과 목표의 차이를 이 비율만큼 줄임 |
| 피부 채도 | 1.0 | 피부 채도 배율 |
| 피부 밝기 맞춤 | 0.5 | 피부 밝기를 Reference 얼굴 피부 밝기 쪽으로 (비율로, 최대 ±12%) |

- **피부 밝기**는 두 이미지 모두 얼굴이 있고 교정 목표가 Reference 피부일 때만 맞춥니다. 큰 노출 차이는 ① 프라이머리의 몫이고, 퀄리파이어로 밝기를 크게 바꾸면 키 경계에서 얼룩이 생기기 때문에 ±12% 로 제한합니다.
- 밝기용 키는 색상용보다 **넓고 부드럽게** 잡고(색상 폭 1.5배, 밝기 ±12, LUT 격자 한 칸 확장), 밝기는 **비율로** 바꿔 피부 결을 유지합니다. 좁은 키로 더하기를 하면 얼굴 안에서 일부 픽셀만 어두워져 얼룩이 생깁니다.

- **퀄리파이어**: 얼굴에서 샘플링한 그레이딩 후 피부 색 범위(위 "피부 인식")만 교정합니다. 입술·립 컬러처럼 피부보다 진한 색은 범위 밖이라 교정되지 않습니다.
- 피부 '보호'와 달리 격자 가중치를 넓히지 않습니다. 넓히면 피부 바로 옆 색인 입술까지 끌려가기 때문입니다.
- 앱에서 교정 전/후 피부 색상각과 **벡터스코프**(스킨톤 라인 표시)를 볼 수 있습니다.
- 예시 이미지: 피부 색상각 19° → 32° (강도 0.5), 입술은 거의 변화 없음(−3.2° → −3.2°), 피부 외 영역 ΔE 0.01.

### LUT 합성과 내보내기

- **전체** LUT 는 각 격자점에 ①②③ 을 적용한 뒤 ④, ⑤ LUT 를 삼선형 보간으로 차례로 통과시켜 하나로 합칩니다. 노드 LUT 를 차례로 건 결과와의 차이는 평균 ΔE 약 0.7 (육안 구분 불가) 입니다.
- 노드 1 → 2 → 3 → 4 → 5 LUT 를 차례로 건 결과는 앱 결과와 같습니다.
- `.cube` 는 표준 순서(**R 이 가장 빠르게 변함**)로 저장되며 `DOMAIN 0~1` 입니다.

### 매칭 방식

| 방식 | 언제 | 동작 |
|---|---|---|
| **룩 옮기기** (`match_mode="look"`, 기본) | 다른 장소·장면에 레퍼런스의 룩을 입힐 때 | ①③ 안전 범위, ② 중성색을 회색으로 |
| **같은 장면의 컷 맞추기** (`"same_scene"`) | 같은 장면을 반대편에서 찍은 컷(리버스 숏)처럼 이미 같은 노출·그레이딩인 두 컷 | ① 끔, ② Reference 중성색에 맞춤(강도 1) |

같은 장면의 두 컷은 밝기 분포가 달라도 그건 화면 내용 차이입니다. 실제 리버스 숏 두 컷에서 타깃이 원본에서 바뀐 정도(평균 ΔE, 작을수록 좋음): 이전 기본값 12.9 → 룩 옮기기(새 기본값) 9.7 → **같은 장면 컷 맞추기 2.2**.

## 한계와 주의사항

- **색공간**: 8비트 Rec.709 디스플레이 이미지 기준입니다. 로그/RAW 소스용 입력 변환은 아직 없습니다.
- **프라이머리 값은 근사치**입니다 (위 "DaVinci 수식과의 차이" 참고). 안전 범위를 끄고 노출 차이가 매우 큰 사진을 맞추면 Gamma 등이 넓은 허용 범위 끝(0.3~3.0)에 닿을 수 있습니다.
- **내용 차이는 따라가지 않습니다**: 장면 구성이 다르면(예: Reference 에 검은 옷이 많음) 섀도우 분포가 완전히 같아지지 않습니다. 의도된 동작이며, ① 은 블랙·화이트 같은 대응 지점만 맞추고 미드톤·계조는 안전 범위로 관리해 이 차이를 노출로 착각하지 않게 합니다.
- **피부 범위는 얼굴에서 정하지만 적용은 색 기준입니다.** LUT 는 위치 정보를 쓸 수 없어서, 피부와 같은 색의 배경(따뜻한 조명 아래 나무, 모래 등)도 함께 보호·교정됩니다. 앱이 경고를 띄우니, 그런 장면은 DaVinci 의 윈도우/트래킹과 함께 쓰세요.
- **클리핑된 정보는 복원할 수 없습니다**: 날아간 하이라이트, 뭉개진 섀도우의 디테일은 LUT 로 되살릴 수 없습니다.
- **같은 장면의 컷**은 '같은 장면의 컷 맞추기'를 쓰세요. 서로 다른 카메라를 같은 조명·구도에서 맞추는 작업(ColorChecker 촬영)이라면 분포 전이보다 픽셀/패치 대응 기반 방식이 더 정확합니다.
- **업로드 파일은 `web_uploads/` 에 계속 쌓입니다.** 배포 전에는 저장하지 않도록 하거나 주기적으로 정리해야 합니다.
